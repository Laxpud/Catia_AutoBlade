# 输入数据格式

## 目录约定

默认输入位置：

```text
input/
  airfoils/        翼型点云 CSV
  section_params/  截面参数 CSV
```

这些是 `config.toml` 的默认目录。输入树可以通过 `paths.input_dir` 整体迁移，也可以分别设置翼型和截面参数目录；完整路径解析规则见[运行时配置](configuration.md)。

## 启动前校验与错误定位

翼型和截面参数文件会在启动 CATIA 前全部解析并校验。错误采用以下格式，包含绝对文件路径，并在适用时给出 CSV 行号和字段：

```text
C:\project\input\airfoils\foil.csv: line 18, field 'y': expected a finite number, found 'bad'
```

因此输入问题不会创建隐藏 CATIA 进程。批处理中，每个组合也会先完成本次输入校验，再创建其独立 CATIA 会话。

## 坐标系与单位

- 输入翼型、截面弦长和三维平移统一使用 m；旋转使用 deg。
- 输入翼型位于 Y-Z 平面，`x` 应为 0 m。
- 输入弦向坐标 `y` 从前缘 0 m 变化到后缘 1 m，因此基准翼型弦长固定为 1 m。
- `z` 是以 m 表示的厚度坐标。
- Python 领域计算执行 `model_y_m = -input_y_m + 0.25 m`，因此模型 X 轴位于 1/4 弦线，前缘指向模型 Y 正方向。
- 创建各截面时，程序使用 `scale/m / 1 m` 作为无量纲缩放因子。
- CATIA Automation 的长度参数固定使用 mm；程序只在 COM 调用边界执行 `value_mm = value_m * 1000`。修改 CATIA 界面显示单位不会改变这一接口规则。

## 翼型 CSV

必需表头：

```csv
x,y,z
```

示例：

```csv
x,y,z
0,1,0.00173
0,0.99628,0.00202
0,0,0
0,0.99628,-0.00202
0,1,-0.00173
```

点序必须满足：

1. 从上侧后缘开始；
2. 沿上表面到达前缘；
3. 沿下表面返回下侧后缘。

解析器还会在启动 CATIA 前检查：

- 文件包含 `x`、`y`、`z` 三列以及至少 3 个有效点；
- 所有坐标都是有限数字，点位于 Y-Z 平面，并且弦向 `y` 位于 `[0, 1] m`；
- 相邻点不重复；首尾相等仍允许用于表示尖后缘；
- 首尾点位于弦向最大值对应的后缘，弦向坐标先非递增到内部前缘，再非递减返回后缘。

前缘是离散点中的弦向最小值，不要求精确等于 `0 m`。点序单调性使用 `1e-9 m` 的数值容差，以容纳正常的浮点舍入，但不会自动重排错误数据。

理论前缘位于输入坐标 `(0 m, 0 m, 0 m)`，但离散点拟合出的 CATIA 样条不保证经过该理论坐标。建模时，程序以该位置作为候选选择器，从每条变换后截面的弦向最大极值中取得实际曲线点；这个点用于 Loft 闭合定位和前缘导引线。

如果第一点和最后一点完全相同，当前实现将翼型视为尖后缘，并直接使用样条作为闭合截面。如果二者不同，则视为钝后缘，程序会用直线连接两个后缘点，再与样条执行 Join。

当前实现使用精确坐标比较，不会按容差合并非常接近的后缘点。输入生成流程应确保尖后缘首尾行完全一致。

## 截面参数 CSV

当前正式读取并校验以下六个米制表头：

```csv
idx,scale/m,translate_x/m,translate_y/m,translate_z/m,rotate/deg
1,0.07094402706,0.16,0.0,0.0,15.004421
2,0.0742,0.1856,0.0,0.0,13.9
```

字段含义：

| 字段 | 类型 | 单位 | 含义 |
| --- | --- | --- | --- |
| `idx` | integer | - | 截面序号；应沿展向递增且唯一 |
| `scale/m` | float | m | 截面最终弦长；相对于 1 m 基准翼型的缩放因子在数值上等于该值 |
| `translate_x/m` | float | m | 沿叶片展向的位置 |
| `translate_y/m` | float | m | 相对 1/4 弦线的弦向偏移 |
| `translate_z/m` | float | m | 垂直方向偏移 |
| `rotate/deg` | float | deg | 绕模型 X 轴的截面扭转角 |

解析器要求上述米制表头，避免把旧版 mm 数据静默解释成 m。所有数值必须有限，`idx` 必须是正整数并按文件行严格递增，`scale/m` 必须大于 `0 m`，且 Loft 至少需要两个有效截面。程序不会主动排序、合并或补齐 `idx`；重复或逆序会定位到对应行并拒绝输入，序号允许不连续。

## `airfoil` 扩展列

工作区中的组合参数样例增加了第七列：

```csv
idx,scale/m,translate_x/m,translate_y/m,translate_z/m,rotate/deg,airfoil
1,0.099129967,0.07874,0,0,36.103446,airfoil1_sharp.csv
```

该列表达“某个截面使用哪个翼型”。解析器会先构造完整叶片输入计划，去重读取所有引用翼型，再启动 CATIA；多翼型模式不接受 CLI 后备 `--airfoil`。

兼容规则如下：

- 没有 `airfoil` 表头的六列文件继续使用 CLI 指定的单个翼型；
- 出现 `airfoil` 表头时，每个有效截面行都必须填写，只能引用配置翼型目录下的精确 CSV basename；
- 引用路径、所有唯一翼型和后缘拓扑必须在启动 CATIA 前完成校验；
- 不要求不同翼型具有相同点数，Loft 通过统一点序、实际前缘闭合点和前后缘导引线建立对应关系。

完整的路径安全、CLI、批处理、输出命名和 Loft 降级策略见[展向多翼型设计](multi-airfoil-design.md)，实现进度记录在根目录 [TODO.md](../TODO.md)。

## 输出命名

单模型默认名称由 `defaults.output_name_template` 根据翼型文件名和截面参数文件名生成，例如：

```text
sc1095.csv + section_params-1.csv
  -> sc1095_blade-1.CATPart
  -> sc1095_blade-1.stp
```

默认模板是 `{blade}`，现有单翼型名称保持上述格式；多翼型使用 `blade-<section-id>`。可用字段及 CLI 输出目录覆盖规则见[运行时配置](configuration.md)。批处理会在输出基准目录下按单翼型名称或多翼型截面文件 stem 增加子目录。已存在的同名输出会在保存前被删除，因此输出目录不应包含需要保留的同名手工模型。
